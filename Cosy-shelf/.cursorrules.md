# You are building a cross-platform HTML5 game for a solo developer.

## TECH STACK (non-negotiable)
- Engine: Phaser 3 + TypeScript. Bundler: Vite.
- Entry point: `index.html` must be in the project root for Yandex packaging.
- UI/Logic: Phaser Scenes. No React/Vue unless explicitly approved.

## PLATFORM ABSTRACTION (critical for multi-platform)
- All platform-specific calls (ads, saves, auth, leaderboards) go through
  `src/platform/PlatformGateway.ts`. Game scenes MUST NOT import `ysdk` directly.
- Concrete adapters live in `src/platform/adapters/` (e.g., `YandexAdapter.ts`).
- New platforms are added by implementing the gateway, not by editing game logic.

## YANDEX GAMES REQUIREMENTS (enforce in every build)
- Yandex SDK must be connected and initialized via the adapter.
- Ads: Only through SDK. Fullscreen ad must pause game and mute audio; resume
  in `onClose`. No custom ad blocks. Rewarded video only on user action.
- `LoadingAPI.ready()` is called only when the game is actually playable.
- File names in `public/` and build output: latin, no spaces/cyrillic.
- Archive size (unpacked) must stay under 100 MB.

## PROMPTING & WORKFLOW RULES
- Before writing code, read the relevant scene/service file and state what you
  will change. Show a diff before replacing existing logic.
- Do not add npm packages outside the approved stack without asking.
- When implementing a feature, always route platform calls through the gateway.
- After implementing ads/saves, add a check: `grep` for direct `ysdk` usage
  outside `src/platform/` must return nothing.

## VISUAL SOURCE OF TRUTH
- Game visuals follow the project's asset pipeline and Phaser scene setup.
  There is no Figma source for game screens. If a visual decision is ambiguous,
  ask before inventing a style.
