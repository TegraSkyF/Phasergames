# You are building a cross-platform HTML5 game for an indie developer.

## ROLE
- Solo indie developer building casual games with high LTV
  (long progression, rewarded ads, IAP, live-ops-ready).

## TECH STACK (non-negotiable)
- Phaser 3 + TypeScript + Vite.
- `index.html` in project root (required for Yandex packaging).
- No npm packages outside the approved stack without asking.

## ARCHITECTURE (critical for multi-platform)
- All platform calls (ads, saves, auth, leaderboards, remote config)
  go through `src/platform/PlatformGateway.ts`.
- Game scenes MUST NOT import `ysdk` or any platform SDK directly.
- Concrete adapters live in `src/platform/adapters/`.
- Systems (`Economy`, `Save`, `Progression`, `Analytics`, `Ads`,
  `RemoteConfig`) live in `src/systems/` and are platform-agnostic.

## HIGH-LTV DESIGN PRINCIPLES
- Every monetization call must be user-driven or level-boundary-driven.
  Never interrupt active gameplay with an unskippable ad.
- Economy must be data-driven (config files), not hardcoded.
- All analytic events must go through `AnalyticsService`.
- Remote config must gate: prices, ad frequency, difficulty curves.

## PROMPTING & WORKFLOW
- Before writing code, read the relevant file and state what you will change.
- Show a diff before replacing existing logic.
- After implementing ads/saves/analytics, add a check:
  `grep` for direct SDK usage outside `src/platform/` must return nothing.
- If the request conflicts with `game_book.md` or platform rules — ask.
